## Summary

Implemented folder-based board grouping for Smart Collections — the stated
prerequisite for the full folder-grouped kanban (card move, create-in-folder).
Notes with no frontmatter can now appear on a board grouped by their containing
directory.

## What changed

1. `CollectionResults.tsx`:
   - Added `FOLDER_GROUP_BY = "file.folder"` sentinel constant.
   - Added `folderColumnKey(note)` helper (whitespace-trimmed, empty → Unassigned).
   - `groupKanbanColumns` now handles `groupBy === FOLDER_GROUP_BY` separately
     from property-based grouping.
   - `hasAnyFolder` check: Board button enabled when notes have distinct
     folders, even without indexed frontmatter properties.
   - Grouping selector shows a "Folder" option when `groupBy === FOLDER_GROUP_BY`.

2. `collectionDecode.test.ts` — 4 new tests:
   - Groups notes by folder with correct counts and column order.
   - Routes notes with empty/whitespace folder to Unassigned.
   - Trims whitespace from folder keys.
   - Verifies property-based and folder-based grouping are independent.

3. `collectionPhase2.test.tsx` — 3 new tests:
   - Board button enabled when notes have folders (no frontmatter).
   - "Folder" option present in the grouping selector.
   - Board renders folder-grouped columns (Inbox, Projects) with no Unassigned.

## Remaining work (roadmap)

The full "folder-grouped kanban" item includes:
1. **Card move**: dragging a card into a different folder column moves the
   note file to that directory. Requires a Tauri command for file rename
   (or use the existing `rename_path` command with a containment check).
2. **Create-in-folder**: creating a new note in a folder column places the
   new file in that directory. Requires a Tauri command for file creation
   with folder path.

Both are plain-filesystem operations on the user's own notes. They depend on
this grouping prerequisite and the existing `rename_path`/`create_dir`
commands (already containment-checked per `rm-60f748cb1a58be89`).
