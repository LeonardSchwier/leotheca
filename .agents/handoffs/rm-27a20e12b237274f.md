## Self-review findings

1. The existing guard in App.tsx (`isPathWithinWorkspace`) already handles
   the core containment check. The gap was the absence of a size cap and
   the absence of regression tests for the specific traversal variants.
2. The new 4096-char cap is generous for any plausible vault depth on every
   platform and far below any realistic URL-length limit. It is applied at
   parse time in `parseAutomationUrl`, before App.tsx's handler runs, so it
   covers all callers of the parser.
3. The traversal tests use `openUrlListeners` (the real Tauri/Capacitor
   deep-link dispatch path) rather than calling `handleOpenFile` directly,
   so they exercise the full guard chain: URL parse → path extraction →
   workspace containment → read.
4. No new dependencies introduced. No API shape changes.
