## Self-review findings
1. `addCard` signature changed from `(filePath?: string)` to `(x?: number, y?: number)`. The "New card" button calls `addCard()` (no args → cascade position). The "Link file" button now calls a new `addFileCard(filePath)` helper with the same cascade logic. No behavior change for existing buttons.
2. The `onDblClick` guard `event.target !== event.currentTarget` correctly prevents card creation when double-clicking a card's textarea (preserves browser text-selection behavior).
3. `Math.max(0, x)` / `Math.max(0, y)` clamp prevents negative coordinates.
4. **Weak test noted**: The "does not create a card when a card itself is double-clicked" test uses `fireEvent.doubleClick(card, ...)`, which dispatches a `Doubleclick`-type event that Preact's `onDblClick` doesn't listen for. The test passes by accident (Preact never receives the event) rather than by the `target !== currentTarget` guard. The guard IS verified by the other two tests (which dispatch `dblclick` directly on the viewport). Fixing this requires a `dispatchEvent` on the card element that bubbles to the viewport, which is more complex in jsdom. Recorded as a known limitation.
5. No accessibility impact: double-click is a mouse interaction; the viewport already has `role="group"` and `aria-label`.
