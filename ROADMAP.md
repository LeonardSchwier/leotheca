- ✅ **Expand-All Native Traversal**: Replace expand-all's per-directory bridge calls with a single native recursive walk (`find_all_entries` on desktop, `findAllEntries` on Android) covering both files and directories, so a directory with nothing directly inside it is still discovered and expanded, not just one containing a file somewhere in its subtree, which a files-only walk could never report. Verified with Rust unit tests (including one asserting an empty directory survives the walk) and TypeScript unit tests for the grouping logic, plus the full desktop verification suite. The Android-side walk mirrors the already-shipped `findAllFiles` pattern exactly (same `DocumentFile`/SAF APIs, same depth cap) but native Android code isn't unit-testable here; CI's Android build is this change's actual verification gate for that platform, no on-device confirmation is claimed.
- ✅ **F-005: Search memory guard — `isTextFile` whitelist, batch size pre-add flush, conservative unknown-size default**: The audit (F-005) found three gaps in the search content-read batching that had already been fixed in layers 1-3 (file count cap → byte size cap → oversized file skip) but left residual risks: (1) non-text files (PDFs, videos, archives, executables) were passed through the native side's string serialization — on Android `ByteArrayOutputStream.toString("UTF-8")` replaces invalid bytes rather than rejecting them, producing garbage; on Rust the file was read but wasted IPC and memory on content never meant to be searched. Fix: added `isTextFile(path)` in `types.ts` with a conservative whitelist of text extensions (md, txt, html, json, code files, config files, etc.); non-whitelisted extensions are treated like images — matchable by name but never content-read. (2) The old batch size check (`pendingBytes += size; if (pendingBytes >= cap) flush()`) added the file's size *then* checked, allowing one batch of three 5 MB files to go out at 15 MB. Fix: changed to check `pendingBytes > 0 && pendingBytes + size >= cap` *before* adding, then add and flush, ensuring no batch ever grows unboundedly. (3) When the native walk doesn't report a file's size, `entry.size` was `?? 0`, letting an unknown-sized file blend into a zero-size batch and defeating the byte cap. Fix: added `CONSERVATIVE_UNKNOWN_SIZE = 4 MB` — when size is unknown, the batch assumes 4 MB so one batch can never hold more than two unknown-size entries. Verified by 10 new tests (non-text file exclusion, batch size bound enforcement, unknown-size default behavior, realistic-size batching) plus all 597 existing tests, `tsc --noEmit`, `vite build`, and `cargo check` green.
- ✅ **Audit follow-up N-004: Contain local Markdown attachment reads**: Adds a canonical workspace-aware lexical read-containment helper for preview attachment paths and requires local Markdown images to pass it before `fileSrc()` can run. Absolute paths, traversal escapes, out-of-workspace bases, component-prefix confusion, and Windows-style traversal are rejected without a native read, while valid nested and sibling attachments remain supported. A negative-control CI run on the pre-fix claim commit proved the escape regression reached `fileSrc()`, while final implementation CI passed frontend typechecking, the full frontend test suite, production build, Rust check/tests, Capacitor sync, and the Android debug APK build. - ✅ **Audit follow-up N-005: Bound Markdown attachment resolution concurrency**: Replaces unbounded local preview attachment reads with a six-worker queue. Rerender or unmount stops stale workers before they schedule more queued reads, already-invoked reads cannot mutate obsolete DOM, and one failed attachment does not block the remaining current queue. Tests-only negative-control CI run `33353118131` proved the pre-fix preview started all 12 requested reads and all 10 obsolete reads immediately; implementation CI run `33353227555` passed the same focused regressions plus frontend typechecking/tests/build, Rust check/tests, and the Android debug APK build. No Android on-device verification is claimed.
- ✅ **Audit follow-up F-009: Preserve frontmatter semantics during property edits**: Properties edits now replace only the selected field source range instead of rebuilding the whole frontmatter block. Existing ordering, comments, CRLF/LF endings, unrelated booleans and numbers, and unsupported YAML remain byte-for-byte unchanged. Plain, single-quoted, and double-quoted scalar styles are retained for safe selected edits; nested structures, multiline values, and ambiguous quoted-comma lists are shown read-only rather than normalized. Golden regression fixtures cover all required cases. A pre-fix negative control reproduced unrelated scalar normalization and comment movement; implementation run `33354455523` passed frontend typechecking, 622 tests, production build, Rust check/tests, and the Android debug build. No Android on-device verification is claimed.
- ✅ **Audit follow-up F-006: Give search requests explicit ownership**: Full-text search now carries a monotonically increasing request generation together with workspace-session identity, so stale enumeration or content-batch completions cannot replace newer results, undo a clear, or clear the newer request's loading state. Search authority is invalidated on clear and workspace reset, including Android grant changes that retain the synthetic `/workspace` path. Tests-only CI run `33356013650` failed all five intended pre-fix races: both A/B completion orders, clear during A, stale content-batch completion, and a workspace-session switch. Implementation CI run `33356099917` then passed frontend typechecking/tests/build, Rust check/tests, Capacitor sync, and the Android debug APK build. No Android on-device verification is claimed.
- ✅ **Audit follow-up F-013: Measure and bound graph layout work**: Graph layout now retains exhaustive pairwise forces for small graphs but caps larger layouts at 500,000 estimated force interactions using deterministic repulsion sampling and bounded attraction-edge sampling. Same-turn layout requests coalesce behind generation ownership, and a result must still own the latest generation after computation before it can publish. Representative 100, 500, 2,000, and 5,000-node budgets are covered, with a 2,000-note chain benchmark that ran in about 79 ms on CI and has a generous 2-second regression ceiling.
