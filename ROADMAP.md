- ✅ **F-005: Search memory guard — `isTextFile` whitelist, batch size pre-add flush, conservative unknown-size default**: The audit (F-005) found three gaps in the search content-read batching that had already been fixed in layers 1-3 (file count cap → byte size cap → oversized file skip) but left residual risks: (1) non-text files (PDFs, videos, archives, executables) were passed through the native side's string serialization — on Android `ByteArrayOutputStream.toString("UTF-8")` replaces invalid bytes rather than rejecting them, producing garbage; on Rust the file was read but wasted IPC and memory on content never meant to be searched. Fix: added `isTextFile(path)` in `types.ts` with a conservative whitelist of text extensions (md, txt, html, json, code files, config files, etc.); non-whitelisted extensions are treated like images — matchable by name but never content-read. (2) The old batch size check (`pendingBytes += size; if (pendingBytes >= cap) flush()`) added the file's size *then* checked, allowing one batch of three 5 MB files to go out at 15 MB. Fix: changed to check `pendingBytes > 0 && pendingBytes + size >= cap` *before* adding, then add and flush, ensuring no batch ever grows unboundedly. (3) When the native walk doesn't report a file's size, `entry.size` was `?? 0`, letting an unknown-sized file blend into a zero-size batch and defeating the byte cap. Fix: added `CONSERVATIVE_UNKNOWN_SIZE = 4 MB` — when size is unknown, the batch assumes 4 MB so one batch can never hold more than two unknown-size entries.
