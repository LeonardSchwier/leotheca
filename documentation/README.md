# Technical documentation

This directory is the canonical home for technical documentation. Start with the first section, then pick the document for the part you need.

## Start here

- [`ARCHITECTURE.md`](ARCHITECTURE.md): system boundaries, platform bridge, module ownership, data model, build paths, testing strategy.
- [`TESTING.md`](TESTING.md): unit tests, end-to-end tests, CI smoke tests, UI verification and how to regenerate the README screenshots.
- [`../CONSTITUTION.md`](../CONSTITUTION.md): the binding policy for anyone, human or agent. Not duplicated here.
- [`../ROADMAP.md`](../ROADMAP.md): what is planned and shipped. Not a design specification.

## How the project is run

- [`AGENTIC_PDLC.md`](AGENTIC_PDLC.md): the agent-run lifecycle stage by stage, the enforcing files and the known gaps.
- [`BRANCH_MODEL.md`](BRANCH_MODEL.md): protected main, pull-request delivery, the merge queue and the ledger branch, with the rollout phases.
- [`PROJECT_RULES.md`](PROJECT_RULES.md): the product rules agents read before changing the app.
- [`REPO_SETUP.md`](REPO_SETUP.md): every governance and hygiene file, and what actually enforces it.
- [`REUSE_AGENT_ORCHESTRATION.md`](REUSE_AGENT_ORCHESTRATION.md): how to reuse this orchestration in another repository.
- [`DECISIONS.md`](DECISIONS.md): archive of historical decisions, superseded by the constitution where they differ.

## Subsystem notes

- [`ANDROID_WIDGETS.md`](ANDROID_WIDGETS.md): offline home-screen widgets and their local URL commands.
- [`GRAPH_LAYOUT.md`](GRAPH_LAYOUT.md): the bounded force-directed layout of the graph view.
- [`INK_DRAWING.md`](INK_DRAWING.md): the foundation slice of freehand drawing.
- [`WORKSPACE_PROFILES.md`](WORKSPACE_PROFILES.md): app-local profiles that point at user-owned folders.

## Screenshots

[`screenshots/`](screenshots/) holds the light and dark PNGs used by the root README, generated by `tests/e2e/screenshots.mjs`.

## Keeping this documentation useful

Update the smallest relevant document in the same change when implementation alters a module's responsibility, a data flow, a platform boundary, storage, a build path, or a verification strategy. Prefer links to duplication.
